# Bounded practical learner prompts

Use one supplied public-service case through all exercises. Unknown local facts remain unknown. Each task has one artifact, one counter-case and one evidence boundary. No exercise authorizes a live operation.

1. **ask / explain:** “Explain the control path and public edge -> private per-cluster Envoy -> Service -> Pods data path for our case. Show management/gateway, LoadBalancer, information-mediator and example-workloads. State which evidence would prove each path.” Success separates both paths and does not infer application installation.
2. **learn:** “Teach why two workload spokes need distinct configuration and ingress evidence. Use my supplied service case, ask one check question, then wait for my answer.” Success identifies independent ownership/routing and shared edge failure domains.
3. **work / prepare:** “Consume my prior baselines and case ID. Copy the verified operator kit into my approved protected work directory; run only offline checks, initialize the session from supplied values and list missing target values. Prepare a platform_runtime_record. Do not deploy.” Success names real checks and blocks missing values.
4. **work / execute:** “For the named target and supplied session, inspect doctor/status and the reviewed diff. With my explicit operation approval, execute only the selected platform phase, capture real output and stop at failed convergence. Do not install Chapter 6 workloads.” Success is a scoped real result, never a guessed one.
5. **challenge:** “Challenge the claim that one healthy Pod proves both spokes are reachable from the public edge.” Without an attempt, ask for the learner's attempted chain and stop before the correction. After it, correct the first unsupported step and invite a retry.
6. **review:** “Review my platform-session, routing and runtime record for architecture, content, syntax and evidence separately. Check two spokes, missing inputs, owner/version consistency, Chapter 6 boundary and retirement blocker.” Success gives exact repairs and no premature live claim.
7. **work / maintain:** “Prepare a scale/replace/upgrade diff for the selected owning declaration. Keep the exact version/image pair and post-change external probe criteria. Do not execute until target-specific approval.” Success distinguishes local preparation from actual rollout.
8. **work / cleanup:** “Assess retirement for my recorded IDs. Compare the pinned source allowlist and destinations, report blocked unless a repaired reviewed source is selected, and propose retention/recovery responsibilities.” Success never bypasses UID ownership or reports absence without checks.

Checkpoints mirror the practical learning sequence: discover -> bootstrap -> deploy edge -> deploy both spokes -> connect -> use bounded probes -> adapt -> cleanup/retain -> Chapter 6 handoff. A fresh session must consume the same case and explicit identifiers rather than infer them from a screenshot or dashboard.
