# Cloud interoperability explainer

Use when an agent must explain the relationship between cloud delivery and interoperability without turning it into a slogan.

## Procedure

1. Define the interoperability problem in the user’s context: data exchange, identity, APIs, common platforms, deployment consistency, or operational coordination.
2. Explain the mechanism that may help: standardised runtime environments, repeatable deployment, managed integration points, common identity controls, or shared observability.
3. State the conditions required for that mechanism to work: agreed standards, governance, API design, security controls, operating ownership, and testing.
4. State the boundary clearly: cloud adoption alone does not create interoperable services.
5. Provide a small set of local questions and deeper topics when implementation detail is needed.

## Output

Return: concept, mechanism, conditions, consequence, caveat, local questions, and deeper routes.

## Boundaries

Do not make claims that cloud automatically delivers interoperability. Do not cite or disclose inaccessible internal sources.
